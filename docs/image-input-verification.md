# Inline image input — scoped verification

## Authorization and status

The operator requested image support, a PR and the normal reviewed production rollout, with **no live/paid inference tests** and no custom image inspection or duplication of Pi's supported image handling. This record initially covers source and offline artifacts only; it is not client installation, running-session activation, gateway deployment or live vision/tokenizer qualification.

[Tinfoil's vision models](https://docs.tinfoil.sh/models/vision) and [image-processing guide](https://docs.tinfoil.sh/guides/image-processing), consulted during this task, document `deepseek-v4-1-flash`, `kimi-k3` and `gemma4-31b` for image input. Flash is marked experimental. Image input is an OpenAI chat-completions user content array with inline base64 `image_url` data URLs. The reviewed exact-ID profile is a local source assumption, **not authenticated capability metadata or per-model runtime qualification**. Live authenticated catalog membership still authorizes availability, context and prices. Other models remain text-only; no model is substituted.

## Small implementation and unchanged boundaries

- Pi's supported `convertMessages` performs image attachment conversion, including moving images from tool results into a user message while retaining matching text tool results. Possums preserves those ordered image/text parts. It does not copy Pi's conversion, decode/resize images, inspect pixels or headers, validate base64/image contents, or add image count/size quotas.
- The gateway accepts user strings or a closed text/image content array. Inline JPEG/PNG/GIF/WebP prefixes with nonempty payloads are admitted under existing defensive HTTP/JSON/serializer bounds. Remote URLs and unsupported part/field shapes are rejected; the gateway never fetches image URLs. Supported SDK `ImageUrl` owns image serialization; absent `detail` remains absent rather than becoming null. The upstream decoder remains responsible for image validity.
- System/assistant/tool content restrictions, matching pending tool results and final-user validation remain. Arrays use the existing structured request path without requiring new tools. No transcript normalization, reasoning replay or tool execution is added.
- Image model admission occurs after verified evidence and authenticated catalog lookup, before reservation or prompt-bearing calls. Maximum-cost reservation still precedes the existing verified tokenizer request carrying the full image parts. The existing SDK builder sends the same parts to generation. Context allowance uses the tokenizer result, never a byte/pixel/text estimate. Tokenizer rejection or context failure prevents generation and follows existing once-only refund/duplicate behavior.
- Submitted prices, 30% markup, bounded delivery, disconnect/cumulative-usage policy, authenticated finish/receipt/DONE/EOF tool gates, no inference replay and existing session-prefix scope are unchanged. Attachments are request content and may participate in provider volatile prefix state; no new retention or erasure guarantee is made.
- Text-only arrays still collapse to text strings in Pi, retaining the shipped text wire. Default catalog fields and response/receipt contracts are unchanged. Only an explicitly submitted image on an unsupported model can encounter the new `invalid_request` / `images_unsupported` detail; normal old text clients cannot produce that newly accepted shape. Current reference/Pi diagnostics preserve the closed request constraint and locally authored remove-images/select-vision action without showing server text.

Privacy references: [data handling](../PRIVACY.md#data-handling-boundaries), [forbidden content/identifying telemetry](../PRIVACY.md#telemetry-permitted-signals-and-forbidden-data), [typed failures](../PRIVACY.md#typed-interface-failures-and-token-aggregate-extension) and [synthetic testing](../PRIVACY.md#synthetic-testing-exception). The new refusal reuses `InterfaceError::InputRefused`; no telemetry family/projection, logger, support bundle, credential handling or persistence is added. Native Pi/T3 history can retain attachments and normal messages independently of gateway memory handling.

## Rollout and activation limits

Use the existing [approved-main release procedure](approved-main-releases.md), required CI, signed independent image builds, current-main admission and protected production approval/serving verification. Do not label this backend PR `no-rollout-needed`. The normal credential-free attestation/serving check is not a paid image canary. No live image inference, upstream image-tokenizer correctness, image billing equivalence, volatile cache erasure or runtime memory headroom is established by offline fixtures or rollout.

Deployment alone cannot repair the original Pi screenshot-history rejection: the installed client bundle must also be replaced under installation authorization, then activated by a user-controlled restart/fresh provider process. No automatic session restart, history rewrite, screenshot deletion or uncertain generation replay is authorized by this patch.
