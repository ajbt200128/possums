## Closed error aggregate contract

`src/failures.rs::InterfaceError` is the closed **54-category** aggregate projection. The existing detailed `InferenceFailure` codes remain the public source; grouped validation categories do not erase those diagnostic codes. No HTTP-status, raw exception text, model output, arbitrary code/string or request field can construct an aggregate category. Only `error_type` is exported with `possums.interface.errors`, integer monotonic DELTA, unit `{error}`. No endpoint/account/model or exception attribute is added.

| Fixed aggregate labels | Boundary meaning |
| --- | --- |
| `input_refused`, `route_refused`, `authentication_refused`, `conflict_refused` | Known input/route/auth/conversation refusals; distinguish transient auth-state failure and ordinary duplicate. |
| `credit_refused`, `account_limit_refused`, `state_capacity_refused`, `account_unavailable` | Independently known credit/concurrency/capacity/account outcomes; no capacity-to-quota inference. |
| `quote_invalid`, `quote_overflow`, `model_unavailable`, `context_refused` | Preserve catalog/quote selection, context and representability failures before reservation. |
| `evidence_unavailable`, `evidence_invalid`, `verification_failed`, `catalog_failed` | Preserve known evidence/trust/catalog source categories without guessing deeper SDK/helper causes. |
| `request_encoding_failed`, `tokenizer_transport_failed`, `tokenizer_http_refused`, `tokenizer_response_invalid`, `tokenizer_upload_incomplete` | Existing typed request/tokenizer stages; use safe observed HTTP status only in local diagnostics. |
| `generation_transport_failed`, `generation_http_refused`, `stream_transport_failed`, `stream_deadline_exceeded`, `stream_idle_timeout`, `stream_decode_failed`, `stream_validation_failed`, `upstream_error_reported` | Existing SDK/stream categories. Reported upstream event does not establish transport failure; downstream delivery is separate. |
| `terminal_evidence_missing`, `terminal_evidence_invalid`, `settlement_failed` | Distinct terminal/accounting constraints; preserve independently failed accounting while keeping primary upstream failure. |
| `header_protocol`, `header_limit`, `body_limit`, `body_deadline`, `connection_capacity`, `connection_deadline`, `response_encoding_limit`, `configuration_invalid` | Locally known protocol/transport/configuration bounds, not guessed faults. |
| `auth_state_unknown`, `accounting_state_unknown`, `request_read_unknown`, `request_dispatch_unknown`, `response_encoding_unknown`, `response_delivery_unknown`, `preflight_deadline`, `preflight_unknown`, `generation_unknown`, `connection_unknown`, `lifecycle_setup_unknown`, `lifecycle_serve_unknown`, `lifecycle_cleanup_unknown`, `catalog_acquisition_unknown` | Closed stage-specific fallbacks (plus independently known preflight deadline). Unknown does not assert panic, cancellation, credential expiry, termination, settlement or refund. |

The sole failure owner increments once after relevant locks return. Propagation/rendering does not increment. Independent secondary delivery/accounting faults may count once without replacing the primary fault. Voluntary cancellation, orderly shutdown, routine duplicate and normal completion are not new failure categories. Table cells **and the across-category sum** must fit `0…i64::MAX`; overflow withholds this family until reset. Empty categories emit no automatic zeros. Source classification remains mandatory with telemetry disabled; exporter failure cannot recursively count into its own exporter.

The frozen additional cardinality is **54 error points + 9 token points = 63** per complete window, with no cross-product dimensions. Existing `REQUEST_SERIES=1051` and expanded `REQUEST_CELLS=3256` imply at most **1114 logical series / 3319 expanded request-window points** for combined materialization. This is a schema bound, not measured SDK allocation or wire evidence. Retain existing hard outbound **6,576,128-byte** transport limit and the existing **8,388,608-byte** qualification allocation budget; do not raise either to make the extension pass. Combined worst-case wire/allocation and exact Rust layout must be measured with the actual supported SDK before qualification. All families share the existing clock/controller/sender ownership; existing request-table linked integrity remains required, with independent extension-family validity and whole-window clock/epoch/reset fencing.

## Pinned numeric token contract

- Three names: `possums.tokens.input`, `possums.tokens.output`, `possums.tokens.cached`; supported integer monotonic DELTA sums with unit `{token}`, sole attribute `possums.model`. Initial closed partition is `kimi-k3`, `glm-5-3`, `other`, yielding **at most nine points** per complete five-minute window. Across-model totals are query sums, never additional points. Unmapped supported models all contribute to `other`.
- Input includes cached input, output includes provider-included reasoning, cached is an input subset. Reuse authenticated `forward::Evidence` and existing completion/last-valid snapshot semantics; no tokenizer estimate, raw evidence object, cost/header/cache scope, second parser or upstream request change.
- Primitive observation accepts only model token and numeric input/output/total/optional cached counts, with input+output==total and cached≤input checks. Counts, every partition cell and every per-metric across-model sum must fit **0…i64::MAX**, matching the pinned supported OTLP integer conversion. Overflow/invalid data withholds the token family without changing inference/accounting; never accept the SDK's zero conversion for out-of-range u64.
- `None` cached means unknown: withhold all cached points for that window, but valid input/output can release. A populated fully cache-qualified partition can publish measured zero; an empty population has no points. No separate usage-coverage metric is authorized.
- Record once at the existing sole generation terminal after accounting returns, using final or last trustworthy cumulative evidence even on interruption/accounting failure. Attribute the whole observation to the terminal window. Never sum snapshots, maximize decreasing snapshots or count duplicate submissions/trailers; metrics do not invoke accounting.
- Foundation implementation uses fixed arrays and flags, no clock, allocation or metadata. Reset with the existing window lifecycle. Exact layout, combined series/payload/allocation budgets and actual supported SDK wire are later measured gates, not inferred from this nine-point bound.
- Extended family coverage/activation remains code-controlled and withheld until qualified. Reuse the existing complete 300-poll clock/controller and immutable request-window send ownership; independent family validity must not relax existing request-table integrity or fabricate healthy zeros. No new timer, sender, queue or persistent state.
