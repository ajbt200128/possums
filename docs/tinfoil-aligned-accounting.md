## Provider documentation and external boundary

- [How usage is recorded](https://docs.tinfoil.sh/admin/admin-api#how-usage-is-recorded): documented streaming billing uses running prompt/generated counters at interruption; pre-response/model HTTP rejection is uncharged; reasoning is included in output.
- [Usage metrics for billing](https://docs.tinfoil.sh/guides/proxy-server#usage-metrics-for-billing): opt in with `X-Tinfoil-Request-Usage-Metrics: true`; metrics are response headers or streaming trailers, with optional cache/feature fields and published `cost_usd`.

These are provider documentation, not invoice or live-endpoint verification. Closing transport does not prove immediate compute termination or memory erasure. Last observed cumulative usage can undercount provider billing; unobserved usage and unexpected/unquoted fees remain operator liability. Never sum snapshots or infer tokens from text. Published provider cost metadata is not a Possums debit.

## Implemented path

- `src/inference/forward.rs` consumes the existing verified, origin-bound reqwest response through its supported native `http::Response<reqwest::Body>` conversion and `BodyExt::frame()`. DATA feeds the SDK SSE decoder; TRAILERS feed a bounded metrics parser. There is no replacement HTTP/TLS/EHBP stack or second SSE parser.
- `ProtocolParser`, custom text SSE parsing, obsolete wire helpers and production role/delta/finish reconstruction were removed. Text/tool production callbacks use the same consumer; the API forwards supported native grouping directly. Historical synchronous resource fixtures are test-only, and synthetic inference implementations retain a bounded compatibility bridge.
- The additive SDK acceptance callback checks payload bytes, depth, node count, duplicate keys and typed unsigned numeric fields before `Value` allocation. This rejects reserved-number-map substitutions under serde_json arbitrary precision. Native choice/tool types still come from the SDK. Supported choice/delta/usage fields are allowlisted; upstream identifiers, arbitrary metadata, errors and the reserved `possums` namespace cannot be forwarded as authority. Tool assembly/schema/execution validation remains caller-owned.
- The existing one-request-per-connection server shares a disconnect signal through preflight and response delivery. Real EOF/read/write failures or body drop cancel tokenizer, generation send/read and capacity waits, not the sole settlement owner. Empty read buffers are not EOF. Delivery awaits byte/frame credit, including retained slices, rather than detaching on a full queue. Backpressure does not start a generation deadline or become a disconnect.
- The same reservation guard commits last wholly validated cumulative evidence, prefers validated terminal metrics at actual EOF, otherwise requires validated final SSE usage, and settles once at the submitted quote. No trustworthy usage/pre-response rejection refunds; accounting failure cannot fabricate a confirmed outcome. Committed evidence also survives panic/drop fallback. EOF-committed money survives later receipt/body loss; an earlier disconnect closes work without draining for final trailers.
- Downstream `src/api.rs` accepts exactly one `X-Tinfoil-Request-Usage-Metrics: true` and advertises `Trailer: X-Tinfoil-Usage-Metrics` on streaming responses. `api_stream`/`DeliveryBody` emit one actual native `Frame::trailers` after queued DATA/receipt/DONE and producer EOF, using a separate at-most-4096-byte slot. Only validated native metrics committed after authenticated upstream transport EOF and a complete settled receipt qualify; running/final SSE counts are not converted to metrics. Incomplete/error outcomes withhold the downstream metrics trailer even after clean transport EOF, without discarding or mutating trustworthy usage/provider metadata used for settlement and the body receipt. The closed summary allowlist is `prompt`, `completion`, `total`, `model`, optional `cached_prompt_tokens`, `uncached_prompt_tokens`, `cost_usd`, `other_cost_usd`, and `web_search_calls`. Unknown fields are omitted; absent provider cost/cache splits are not invented. Disconnects do not drain or wait for metrics. No reference/Pi body contract was changed by this trailer supplement.
- Cached-input prices and validated splits apply to settlement, not a reduced maximum reservation. Checked fixed-point arithmetic performs one final upward rounding and caps liability at the reservation. Reasoning is not added twice. Provider `cost_usd` stays separately named metadata.
- One small authenticated body receipt reports monetary outcome, complete/incomplete status, reservation/charge/refund, submitted rates, markup and selected usage evidence. Paid incomplete settlement is not successful inference or tool authorization. Reference/Pi clients require their terminal receipt/DONE/authenticated EOF gate; truncated receipt delivery remains unknown billing. Nullable/omitted native fields and empty tool arrays are supported without enabling tool execution.
- Pi keeps native bounded transient retries, steering, follow-up and compaction. Each retry is a new submission and may charge again. Incomplete paid/refunded/capped receipts retain confirmed money but never execute partial tools. Earlier uncertain submission-control outcomes remain unknown even when a later receipt confirms money. Display components stay nonnegative/cap-aware; reconciliation uses exact receipts and authenticated balance snapshots without initiating inference.

Gateway payload acceptance is 256 KiB, depth 16 and 8192 nodes. Native DATA feeds are 16-KiB slices; larger HTTP backing allocations may remain retained. Delivery retains its independent bounded byte/frame credit. These are parser/storage bounds, **not whole-process RSS or 4-GiB headroom proof**. Existing HTTP/history/context ceilings and admission limits were not tuned for the new capacity configuration.
