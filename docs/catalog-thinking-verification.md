# Catalog-driven thinking — source-only verification

Status: PR source candidate. Implementation and acceptance checks performed no gateway deployment, client installation/activation, paid acceptance inference or telemetry enablement. The bounded display-name/test follow-up used operator-requested Possums DeepSeek v4.1 Flash delegation; those real service calls are dogfooding, not synthetic acceptance evidence.

## Contract and implementation

- `src/catalog.rs` retains the authenticated boolean `reasoning` and supported upstream `reasoning_params` vocabulary: `effort_map` and `params["/v1/chat/completions"].enable/disable`. Other endpoint templates are outside this API and omitted. Unknown chat shapes/keys/values, explicit null controls, empty templates and malformed effort maps make controls unavailable, not ordinary inference unavailable. The raw catalog transport/price/context validation remains required.
- Supported templates contain only `reasoning_effort` and/or `chat_template_kwargs` with boolean `thinking`/`enable_thinking` and string `reasoning_effort`. Closed effort strings are `none`, `minimal`, `low`, `medium`, `high`, `xhigh`, `max`; `$EFFORT` is a catalog enable-template placeholder, never a submitted value. A placeholder without an authenticated `effort_map` establishes **no effort allowlist**. No GPT-OSS table or model-name special case is added. Fixed non-placeholder enable templates can provide a toggle, including enable-only templates.
- `GET /v1/models` adds metadata only for one exact `X-Possums-Reasoning-Metadata: true` header. Omission, false or duplicate values preserve the previous exact default catalog fields. The updated reference channel opts in. An old gateway ignoring that header remains usable: missing metadata means defaults/no manual controls. Catalog contents remain outside the gateway measurement.
- The same opt-in response carries the authenticated upstream `name` as an optional, bounded, sanitized display string. It is presentation-only and never authorizes availability, pricing, tools or thinking: an absent, empty, oversized or control/escape/bidi-format name is dropped and consumers fall back to the unchanged model id. Default catalog JSON remains byte-for-byte identical, and cached discovery reuses only a safe bounded name, never inference authorization.
- The reference request envelope accepts optional upstream-compatible `reasoning_effort` and `chat_template_kwargs`, not Pi levels or arbitrary options. A nonempty control payload must match a concrete advertised enable/disable configuration, with `$EFFORT` replaced only by an advertised map value. Unknown keys, values, partial/mixed template combinations and null request controls are rejected. Payload replacements are re-snapshotted; the current authenticated catalog revalidates them before submission issuance. Renewed session/catalog acquisition never authorizes stale controls.
- Gateway admission independently validates against its authenticated catalog before reservation or tokenizer prompt transmission. Both text and tool paths carry the admitted controls to **tokenization and generation**, using the existing Tinfoil relaxed builder `.set` (`vendor/tinfoil/src/relaxed.rs:467`). There is no SDK protocol adapter/interpreter. Rejection uses HTTP 400, `invalid_request` / `reasoning_parameters_unsupported`, with a locally authored request-stage/catalog-configuration constraint and instruction to omit controls or refresh metadata, without rejected values. Client pre-dispatch rejection preserves `possums_request_reasoning` with the same actionable catalog constraint. Existing malformed-envelope diagnostics remain unchanged.
- Maximum reservation, submitted quote/30% markup, context allowance, cumulative/final settlement, disconnect cancellation, endpoint/trust verification, terminal receipt/tool gates and no inference retry/replay policy remain unchanged. Controls do not introduce an output cap or authorize tools.

## Pi-only adaptation and omission semantics

`clients/pi/thinking.ts` maps advertised upstream `low/medium/high` keys to Pi's same fixed UI levels, with advertised values retained (for example medium → high, high → xhigh/max). Unavailable Pi levels are explicitly `null` in `thinkingLevelMap`, including **off when no disable template exists**. A fixed toggle exposes `high` as on, not a fabricated effort scale. No controls means Pi reasoning controls are unavailable; that host's nominal nonreasoning off state is not an upstream-disable claim.

Pi **1.0.4** `pi-agent-core/dist/agent.js:307` turns native off into `reasoning: undefined`. Therefore **only `streamSimple`**, including the existing native compaction simple callback, interprets absent reasoning as native off and resolves an advertised disable configuration. If disable is absent it sends no override. Raw `stream` and reference/raw API omission always preserve upstream defaults, even when a disable template exists. Raw Pi OpenAI options `reasoningEffort`/`chatTemplateKwargs` become their upstream snake-case fields; they remain catalog-gated. There is no generic gateway thinking vocabulary.

The pinned Pi `getSupportedThinkingLevels` null-map filtering and OpenAI first-nonempty reasoning-alias rule were inspected. Provider/model/extension/package/TUI/security/settings documentation was reviewed; production build types and runtime peers remain pinned to 1.0.4. No host patches or settings changes were made.

Reasoning deltas (`reasoning_content`, otherwise `reasoning`) become separate balanced native thinking blocks. Null/empty reasoning is valid and creates no synthetic block. Thinking closes on text/tool transitions, success and interrupted/failing delivery; text also remains balanced. Native hooks run before Pi display normalization. SDK history conversion remains supported, but all reasoning replay fields/signatures converted into the wire payload are stripped, including tool-only assistant turns. Thinking is provisional display content, not terminal/tool/billing evidence.

## Privacy and limits

Policy references: [data handling](../PRIVACY.md#data-handling-boundaries), [forbidden telemetry](../PRIVACY.md#telemetry-permitted-signals-and-forbidden-data), [synthetic testing](../PRIVACY.md#synthetic-testing-exception), and the [approved client failure policy](pi-client-failure-policy.md). No logger, request trace, telemetry field, retained raw error/catalog diagnostic or support bundle is added. Existing aggregate rejection uses its unchanged Input category. Hostile synthetic rejected values and exceptions do not appear in gateway error bodies or Pi warning diagnostics. Reasoning is intentionally user-visible output: native Pi/T3 history may retain it under host settings, just as text; this is not whole-process transience or upstream erasure.

Existing legacy-v2 freshness limitations and unresolved native v3 CLI platform-signer mismatch are unchanged. No native CLI v3 verification, provider invoice parity, deployed cancellation/receipt guarantee or retention property is claimed. Public metadata acquisition cannot establish that a particular upstream model honors the control for every request. Installation/activation, rollout and any funded acceptance require separate authorization.
