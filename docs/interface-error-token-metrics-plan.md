## Classification and simplification contract

For each controlled boundary, inventory: operation/stage, supported typed failure source, expected category, unexpected fallback, user-safe code/action, evidence-supported operation/billing outcome, sole counting owner, and synthetic regression. Exhaustive matches must preserve known categories through wrapping and cleanup. Classification must never inspect formatted exception text, URLs, identifiers or user content.

Keep a **small sufficient** set of expected errors: authentication refusal, malformed/unsupported input, unavailable model/context/credit/admission, conflict/duplicate policy, verification/catalog failure, encoding, transport/deadline, decoding/validation, missing terminal evidence, and settlement failure where actually reachable. This is a starting grouping, not a frozen enum or permission to collapse distinct trust/accounting constraints. Separate normal duplicates, orderly shutdown and voluntary cancellation from faults; an observed disconnect is a lifecycle event unless a real failure is established. Expected client refusals and dependency/internal faults must remain distinguishable in queries.

Remove redundant validation only when another authoritative boundary already guarantees the invariant. Keep trust, context, transport/memory, quote/reservation, usage and authenticated terminal/tool gates. Do not loosen unknown security/accounting semantics for forward compatibility. No target error-count quota, invented root causes, blanket catch-and-success, new retries or suppression to make graphs look healthy.

Unexpected failures use locally authored stage-specific types (for example request-dispatch, catalog-acquisition, stream-decode, settlement, response-encode, response-delivery, lifecycle-setup/cleanup **cause unknown**). Pin the final enum after the inventory; no unqualified `unknown_error` bucket. Do not manufacture rollback/refund, credential expiry, provider HTTP status or successful completion. Preserve the first known failure; an independently observed later delivery/cleanup fault is separate, not a relabelled primary fault.

## Selected aggregate shape

All new points use complete, aligned, non-overlapping **five-minute** windows and the existing fixed resources/scope/slot. Locally aggregate before SDK materialization; never send one observation per error/request. Proposed names below must be pinned with exact units, types and enum cardinality in phase 1 before code/export.

### Interface failures

`possums.interface.errors`: integer monotonic DELTA sum, unit `{error}`, sole datapoint dimension `error_type`, a reviewed closed projection of typed failures. Stage-specific unknown categories encode their failing stage in this enum. No raw diagnostic-code registry, endpoint×model×status×stage×error cross-product or dynamic labels. Detailed codes stay transient first-party diagnostics; only the reviewed aggregate projection is exported.

One failure has one owner at its originating operation boundary. Propagating it through route, stream, accounting or formatting wrappers does not recount it. Do not add HTTP/generation/delivery counts to this family as disjoint incident totals. Separate genuinely independent failures, including settlement after upstream failure, retain their own evidence and ownership. Count outside accounting/auth locks with bounded, nonblocking telemetry state. Use existing owner state, not request-ID registries or persistent deduplication.

Use independent family completeness/validity on the existing clock/controller: loss, overflow, unqualified hooks, skipped/late windows or unknown enum values withhold the family. Coverage must be statically qualified before release; timer coverage cannot prove all error hooks exist. Complete inactive error cells remain absent initially, consistent with the existing gateway contract; absence is **not zero errors or healthy**. Do not copy intake's all-zero gauge contract without a separate schema decision. Telemetry/exporter failures are classified transiently but never recursively feed their own error metric.

### Usage tokens

Three integer monotonic DELTA sums, unit `{token}`:

- `possums.tokens.input`: total validated input tokens, **including cached input**.
- `possums.tokens.output`: total validated output tokens, including reasoning tokens already included by provider usage; do not add reasoning a second time.
- `possums.tokens.cached`: validated cached-input subset; never add it to input when calculating total tokens.

Sole datapoint dimension: existing qualified `possums.model` partition (`kimi-k3`, `glm-5-3`, `other` initially). Every supported model contributes, including unmapped models in `other`. Sum the released partitions in queries for **across-model totals**; do not emit an overlapping `all_models` series or independent global counter. Individually naming more models needs a reviewed compiled-map/cardinality update, not automatic catalog enrichment. No endpoint, outcome, account, session, cache secret, pricing or provider-cost label/value. Input+output is derivable; no fourth redundant total-token instrument.

Population is **observed validated upstream usage at the sole generation terminal attempt**, not all submitted history, tokenizer estimates, inferred text length, client receipts or an upstream invoice. Record final authenticated usage on completion or the last trustworthy cumulative usage on interruption, once. Never sum running snapshots, take an artificial maximum instead of the authoritative last snapshot, or count duplicates/repeated trailers again. Attribute the whole observed usage to the terminal window, even for a cross-window generation; do not fabricate per-minute production rates within a generation. Generations without trustworthy usage contribute no invented zeros. These totals are partial operational evidence, not exact provider-wide usage or accounting receipts.

At `Terminal::finish`, project only validated numeric counts/cache-availability from existing evidence, after accounting returns, before the existing terminal observation is consumed. Exclude quote/reservation IDs, metadata headers, provider costs and raw `Evidence` from the telemetry API. A failed accounting attempt does not erase authenticated usage or prove that charge/refund succeeded. Guard against duplicate owner calls using existing linear ownership; never call accounting for metrics.

Input/output share checked usage arithmetic and once-only ownership. Cache availability has independent validity: release the cached family for a window only if **every usage-bearing generation in that window** has trustworthy cache counts. If any is unknown, withhold the entire cached family for that window, rather than report a partial subtotal as total. Input/output may still release if valid. Known zero cache counts for a populated, fully cache-qualified partition are real zeros and may be released; an empty usage population has no token points. No new coverage-count instrument or user tracking. This means cached totals may be unavailable, especially for interrupted streams; changing upstream requests to acquire additional evidence requires separate compatibility review and authorization, not telemetry-driven inference.

Validate nonnegative integers, checked input+output arithmetic, cached≤input, per-family aggregate bounds and exact serialization (including supported SDK signed-integer limits). Pin the maximum representable value and cardinality before implementation; on overflow/loss withhold the affected family, never clamp, wrap or approximate. Telemetry cannot alter valid inference/accounting behavior if its numeric range is smaller.

## Privacy and operational limits

This explicitly expands the earlier token-export prohibition **only for these five-minute sums**. Cost/balance/reservation exports, per-request events, client uploads, content, raw errors and identifiers remain prohibited. No raw evidence object enters telemetry for later redaction. Honeycomb US/provider-default MVP retention, restricted access and `OTEL_SDK_DISABLED=true` remain unchanged; effective retention, platform logging and deletion properties remain separately unknown.

Sparse token totals can disclose one request's approximate prompt/output length and cache reuse; error types disclose failure activity. Across-model sums do not anonymize individual model cells. Combined with existing dimensions, CPU/RSS and timing, these may enable correlation. The operator's requested extension accepts complete sparse five-minute release without introducing minimum counts or linked suppression; it does not provide anonymity, differential privacy, distinct-user guarantees or invoice parity. No partial-window flush, cumulative snapshots, exemplars, persistent spool, replay or automatic diagnostic export.

## Acceptance matrix

- Known auth/input/credit/context/conflict versus trust/catalog/encoding/transport/decoding/terminal/settlement failures remain distinct; every unknown fallback identifies the actual stage without guessed cause.
- Hostile synthetic exception messages, bodies, URL/header/credential/account/cache-scope sentinels, ANSI and nested causes appear nowhere in diagnostics, stdout/stderr, SDK defaults, resources/scopes/datapoints or OTLP. No raw-error logging bridge or support bundle.
- Upstream failure + settlement failure, observed settlement + later encoding/socket failure, cleanup/cancellation/panic/drop races: preserve primary and independent secondary faults, count once, never infer success/refund/termination from disconnect. Normal cancellation/shutdown does not fabricate a fault.
- Usage snapshots (including decreasing last-valid snapshots), duplicate submissions/trailers, cached subset, reasoning inclusion, missing/invalid usage, unknown cache, trustworthy interruption, failure before response, and cross-window terminals produce exact observed sums with no extra accounting work.
- Multi-model vectors cover both named models and several unmapped supported models in `other`; query-summed input/output/cache match the released partitions. Mixed known/unknown cache withholds all cache cells, not input/output; cache zero is released only with complete known evidence.
- Warmup/restart/shutdown partial windows, clock/scheduling faults, overflow, enum/schema injection, pool contention, disabled export and outage: no healthy zeros, partial/replayed batches or blocked service. Existing accounting/requests/settlement/inference counts unchanged.
- Final supported SDK wire inspection confirms names, units, DELTA temporality, model/error enums, boundary-only timestamps, exact integer totals, no exemplars/enrichment, and existing transport/allocation ceilings. Unknown processor/runtime properties remain unknown.
- Shipped-client tests cover auth/catalog/quotes/reservations, errors, running/final usage, SSE ordering/terminal evidence and partial/final receipts; record exact tested versions and unreproducible-artifact gaps. No weakening of verification or tool gates.
