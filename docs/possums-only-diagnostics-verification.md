## Supported implementation and trust boundary

Both runtime versions expose native provider `getModels`, `auth.apiKey.check/resolve`, and `refreshModels` with `stored` and generation/cancellation-checked `publish({persist, update})`. Native login synchronizes through **offline** model refresh. Use those APIs, not a host bundle patch or RPC stdout writes.

- Persist only bounded public selection metadata **after successful verified authentication and catalog validation**, in Pi's existing provider models store (`models-store.json`). One provider snapshot replaces the previous snapshot. No account key, bearer, diagnostic, verdict, report, request, response, transcript or submission data is written by this feature. The existing native auth store remains separate.
- Treat restored metadata as untrusted. Validate fixed provider/API/origin, safe unique IDs, historical limits and costs; reconstruct only the supported fields. Discard arbitrary cached names, headers and extra fields. Invalid metadata supplies no models. At-rest editing can alter discovery; it cannot authorize inference.
- Names explicitly say **last-known metadata · prices/limits not current · inference unavailable**. Numeric cost/context fields remain historical because the native model type requires them; they are neither a current quote nor gateway admission authority. Pi's picker rows show ID/provider; the highlighted Model Name detail carries the warning. A host that discards that name may obscure the warning; no T3 UI qualification is claimed.
- Usable client, live catalog and live listed models remain separate from discovery. Current authenticated catalog replaces discovery rather than unioning it; absent selected IDs fail with `possums_model_unavailable`, without substitution or dispatch. Reference-client live catalog/context/quote/submission checks are unchanged. The catalog remains outside the gateway measurement; discovery is not a claim that these models are currently supported.
- The provider owns one current closed failure in memory, not a separate extension-level copy. Account/session revocation clears it; accepted authentication/catalog recovery clears it. A selected credential scopes a setup failure before authentication completes, but grants no client/catalog authorization. Epochs, cancellation and native generation-checked publication reject late mutations. Session warning deduplication resets at new-session boundaries.
- A bound ordinary agent attempt can return an already observed setup failure through native auth/assistant errors without repeating evidence acquisition, authentication or catalog work. Status stays offline. Existing explicit-submit expiry-renewal eligibility, native gateway retry classification/budgets, stream validation, settlement/refund and receipt handling remain unchanged; discovery does not grant renewal permission.
