## Historical GitHub-only implementation and trust limits

`clients/pi/evidence-cache.ts` holds one replaceable, bounded public entry under absolute `$XDG_CACHE_HOME/possums/pi-public-evidence-v1`, otherwise `~/.cache/possums/pi-public-evidence-v1`. Schema: fixed origin/repository, semantic release tag, raw-manifest digest, attestation-byte hash hint, exact manifest/provenance bytes. No reports/chip IDs, verdicts, authenticated clients, credentials/bearers, account/request/history data or diagnostic payloads are retained. Temporary atomic-publication files contain the same public schema. Local coordination directories contain only ephemeral process ID, acquisition deadline and random owner nonce; they are not user/account cache keys or exported events. A crash can leave one public temporary file or owner directory; subsequent acquisitions reclaim dead/expired owners. There is no TTL for evidence, cache history, background refresh or credential lookup.

`connectPublished` fetches fixed public attestation first without credentials. Every hit feeds its current report plus fresh AMD certificate, gateway certificate and live HPKE keys into the existing complete verification path. New acquisitions still discover GitHub latest, use the existing bounded approved redirect, and obtain the provenance for the exact manifest digest. Publication follows successful channel qualification. Entries are untrusted inputs; malformed/partial/wrong-namespace/digest entries are misses, whereas failed cryptographic/publisher/hardware/measurement/certificate/key verification is terminal with no fallback. Storage/coordination failures have closed `possums_evidence_unavailable`, stage `public_evidence_cache`, constraint `storage`, without paths or native exceptions. Explicit-manifest compiled approval acquisition remains independent.

Inspected actual pinned `@tinfoilsh/verifier` `verifyBundle`, `verifySigstoreBundle`, bundled trusted-root loading, and existing `qualifyApproved`/`Channel.published`. These rerun verification from bytes; Sigstore signing-time policy is not an acquisition TTL. Each new context retains the existing at-most-12-hour lifetime capped by the currently verified gateway certificate. Cache data neither supplies nor extends an expiry. No new latestness, immediate revocation, anti-rollback or legacy-v2 attestation freshness claim is made. The unresolved native CLI v3 platform-signer mismatch remains outside this accepted legacy-v2 Pi path. No accounting, replay, renewal eligibility or retry-budget changes were made.

Coordination uses Node filesystem primitives (no available locking dependency in the existing lockfile): exclusive directory acquisition and a unique nonempty owner child. Only the successful remover of that unique child may remove its parent, preventing competing reapers from removing a replacement owner. Waits honor the existing operation signal/deadline; acquisition-owner expiry uses the existing bootstrap bound, not evidence age. Publication checks current ownership and cancellation. Filesystem operations themselves are not OS-level cancellable; hung filesystems or hostile same-UID modification are not a sandbox guarantee. A pre-publication owner check plus atomic replacement is not a transaction against hostile concurrent filesystem manipulation. Each resulting entry remains hint-tagged/untrusted and must reverify; no stale publication can grant authorization.
