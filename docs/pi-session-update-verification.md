# Pi session-scoped gateway update qualification

## 2026-10-09 source candidate

The operator approved the MVP in [the plan](pi-update-plan.md): the fixed Possums repository/publishing workflow authorizes releases through the existing signed Tinfoil artifact. New Pi trust sessions acquire and verify public evidence before credentials. Release/key/validity remain fixed within a session; account changes and catalog refresh cannot select another release. Interrupted inference is not replayed. No TUF, persistent update database, hot swapping or smooth cutover is included.

Policy: [data handling boundaries](../PRIVACY.md#data-handling-boundaries), [forbidden diagnostic exports](../PRIVACY.md#telemetry-permitted-signals-and-forbidden-data), and [required evidence](../PRIVACY.md#required-evidence-for-every-telemetry-change). This client does not introduce telemetry. Diagnostics remain closed, locally authored, transient and content-free.

Fresh Node 24.13.0 / Pi 1.0.4 scratch compilation and offline checks passed: 31 reference checks, 379 tool-client checks, 98 release-policy checks, 57 Pi checks and 71 admission checks. One initial run failed solely because an existing diagnostic assertion expected uppercase `Check connectivity`; matching that instruction case-insensitively passed the complete rerun. The default devenv shell selected another Node version and was rejected by the build guard; the fresh build used the existing pinned Nix Node 24.13.0 binary without changing the guard.

The release-policy suite uses actual SDK orchestration, Sigstore identity-policy helpers, subject/tag/measurement comparison, SAN decoding, SHA-256, gzip bounds, local expiry and EHBP config decoding. AMD hardware signature verification, DSSE/Rekor cryptography, certificate parsing and public network responses are mocked in its isolated synthetic bundle only. Tests confirm the production bundle contains no hardware mock hook and rejects synthetic reports/fixture construction. Negative vectors cover signatures, signer/repository/workflow/tag/source/invocation, manifest/raw-byte/predicate/config-hash mismatch, hardware/key/SAN mismatch, expiry, redirects, cancellation, hostile diagnostics and zero acquisition retry.

The native Pi runtime fixture runs one process through startup, logout/login, stopped gateway A, `/new` to B and resume. It observes one trust verification per session, no account-triggered release refresh, fail-closed old-session delivery with unknown billing, and no inference replay on session replacement/resume. Its gateways, authentication and receipts are synthetic; this is not a live replacement or billing observation.

Separately, the fresh production-policy bundle passed real public `connectPublished()` verification against serving **v0.0.15** under an empty environment with an isolated home. It verified the downloaded signed artifact and hardware/key binding through the pinned JavaScript legacy-v2 libraries, sending **zero credentials and zero inference**. This is public bootstrap evidence, not live catalog, tools, compaction, settlement or a deployed update test.

Published session validity is bounded by the earlier of twelve hours after verification and certificate expiry. This is not quote freshness, anti-rollback, newestness or immediate revocation. The publishing workflow is the release authority; its compromise can authorize unwanted code. Compiled API approvals retain their October 11 administrative expiry, and WEB approval remains independent. Node HTTPS is not TLS socket pinning; encrypted bodies/replies bind to the endorsed HPKE key. Legacy-v2 freshness limitations and the unresolved native CLI v3 platform-signer mismatch remain unresolved.

Independent read-only source review reported no concrete defects, while correctly distinguishing synthetic release/lifecycle fixtures from live transition evidence. Combined quota/telemetry integration, exact-head CI, publication, installation and rollout remain pending at this checkpoint. No e2e or whole-runtime privacy claim is made at this source checkpoint. The operator subsequently authorized rollout after those gates and focused real inference tests. Admin demo-credit adjustment was separate at this checkpoint: the existing write-only account secret could not be replaced with a guessed account list. The operator subsequently explicitly authorized an administrator-only reconstruction from the existing locally stored credential; rollout and its encoding correction are recorded below.

## v0.0.16 installed-bundle live checkpoint

[The combined rollout record](combined-rollout-verification.md#v0016-deployment-and-live-checkpoint--2026-10-09) records exact-head CI, reproducible image identity, signed publication, stop-confirm-deploy and credential-preserving installation. Using the installed extension with Node 24.13.0 and actual Pi 1.0.4 SDK sessions, authenticated catalog loading returned seven models. A separately operator-authorized synthetic DeepSeek tool-loop check completed one echo execution and two assistant turns with two authenticated settled receipts. Conversation/credential storage was in memory; no transcript or raw diagnostic data was retained. This qualifies the observed initial-session catalog/tool-continuation/settlement path only, not all models, compaction or uncertain-delivery recovery. The initial tool-disabled harness run had a settled response but did not qualify tools; it was not an upstream failure.

Initial live native replacement attempts correctly failed closed on AMD certificate HTTP 429 and later GitHub discovery HTTP 403, with exhausted unauthenticated allowance confirmed from public metadata. Those new sessions had `evidence_unavailable`, no catalog and no inference. After waiting once for that allowance's observed reset and spacing the two verifications by 65 seconds, native `/new` **passed in the same actual Pi process**: distinct old/new session objects, two successful independent trust verifications, native `startup`/`new` events, serving v0.0.16 selected again and seven authenticated models. The new session completed one echo execution and two assistant turns with two authenticated settled receipts and no failed turn. Normal SDK session managers wrote the synthetic transcript only in a private temporary directory removed by the harness's `finally` block after SDK disposal; credentials remained in memory. The early harness variant that replaced the native manager with an unrelated in-memory manager was corrected before acceptance.

This qualifies same-release live replacement and subsequent tool continuation, not a live A→B rotation, resume or compaction. Public AMD/GitHub rate limits remain availability dependencies; rapid session creation is not promised. No verification bypass, retry of uncertain inference or additional cache was introduced. The earlier local A→B fixture remains synthetic evidence, not a live cutover result. Installed package selection is not proof that the operator's already-running interactive Pi process restarted; the required first full restart remains an operator action. Legacy-v2 freshness, native CLI v3 signer mismatch and whole-runtime privacy limitations remain unchanged.
